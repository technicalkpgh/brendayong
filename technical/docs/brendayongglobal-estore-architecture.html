E-Store System Architecture Guide

Maintainer Reference: Modular Google Apps Script Backend & Web Frontend

1. Modular File Breakdown & Responsibilities

File Name Primary Responsibility
Constants.gs Centralized configuration flags, sheet names, folder IDs, column index mappings, and status constants.
Code.gs Web app entry point (doGet), custom spreadsheet menu creation (onOpen), and utility/test scripts.
Admin.gs Server-side modal trigger functions and action handlers called from admin interfaces via google.script.run.
Estore.gs Customer storefront catalog fetching (getBooks) and end-to-end checkout processing (processOrder).
EbookServices.gs Google Doc template copying, placeholder replacement (body/footer), PDF conversion, and URL map serialization.
EmailServices.gs Dynamic notification recipient configuration lookup, receipt building, and customer/admin email dispatch.
Utilities.gs Shared helper functions like sheet getters and order detail parsers for admin modals.

2. Customer User Flow (End-to-End Checkout)

  1. Catalog Browsing: The user opens the storefront (`Index.html`). The book catalog is loaded dynamically from the "Book List" sheet, displaying titles, prices, descriptions, and cover images.
  2. Cart Selection: The user selects the desired quantities for their books and proceeds to the shipping/checkout phase.
  3. Fulfillment Options & Rules:
    • Digital-Only Orders: If the cart contains only eBooks, the system restricts fulfillment exclusively to Digital Delivery.
    • Physical / Mixed Orders: If physical books are present, the user can choose between Self-Collect or Courier (restricted to Malaysia only, with a flat rate applied).
  4. Shipping Details: If courier delivery is chosen, the user enters their delivery address, postcode, town, state, and country.
  5. Payment Process: The user proceeds to payment, scans the provided bank QR code, uploads their payment receipt file, and submits the order.
  6. Confirmation & Processing: Upon submission, an order ID (`ORD-XXXXXX`) is generated, the order is logged to the sheet with status Submitted, a confirmation email is dispatched to both the customer and admin, and order processing begins.

3. Administrator Capabilities & Management Actions

Admins manage orders directly via the custom "Order Management" menu integrated into the Google Sheet UI:

  • Verify Payment: Open the verification modal to inspect order rows, review payment statuses, and shift order statuses from Submitted to Processing (marking payments as Verified).
  • Generate Watermarked PDFs: Manually trigger watermarked eBook generation for orders using master Google Doc templates, injecting buyer placeholders into both the body and footers, and saving downloadable PDF links.
  • Update Courier Details: Record and update physical shipping tracking metadata (shipping date, courier company name, and tracking number) for physical/mixed fulfillment orders.
  • Fulfill eBooks (Send Email): Review digital items, choose whether to reuse cached watermarked PDFs or generate fresh ones, save links to the sheet, and automatically email secure download links to the buyer.
  • Complete Order: Review final order states and stamp the order status as Completed to close out the transaction lifecycle.

4. Order Lifecycle & Status Workflow

  1. Submission: Customer submits checkout via Index.html. Estore.gs:processOrder() generates an ORD-XXXXXX ID, uploads payment proof to Drive, serializes item details into RawOrderItemData, and sets order status to Submitted.
  2. Payment Verification: Admin uses the Verify Payment modal. Admin.gs:executeVerifyPayment() shifts the order status to Processing and payment status to Verified.
  3. Fulfillment Tracks (Decoupled):
    • Digital (eBooks): Admin triggers Fulfill eBooks. System checks/generates watermarked PDFs via EbookServices.gs, saves download links to column 11, and emails links to the buyer.
    • Physical (Courier): Admin updates tracking details via Update Courier Details, recording date, company, and tracking number independently.
  4. Completion: Admin marks the order as Completed using the Complete Order modal.
